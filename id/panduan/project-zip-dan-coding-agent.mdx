## Isi Project ZIP

ZIP menyatukan keputusan produk, versi dokumen, handoff implementasi, dan workflow agent. Nama file yang spesifik untuk project memakai bentuk aman dari judul Blueprint. Gunakan `manifest.json` yang benar-benar ada di arsip sebagai daftar acuan karena artifact implementation source kondisional dapat berbeda menurut project.

### File produk dan dokumen

| File atau folder | Kegunaan dan otoritas |
| --- | --- |
| `Blueprint-PRD-<Project>.md` | PRD implementasi terkonsolidasi dalam urutan pipeline. Gunakan sebagai sumber utama untuk scope, requirement, acceptance criteria, dan traceability yang disetujui. |
| `PRD-Human-Lengkap-<Project>.md` atau `Complete-Human-PRD-<Project>.md` | PRD yang mudah dibaca dengan App Map berbentuk tree. Gunakan untuk review produk; file ini tidak boleh diam-diam mengganti PRD terkonsolidasi. |
| `Skema-Database-Lengkap.md` atau `Complete-Database-Schema.md` | Kontrak persistence lengkap. Gunakan untuk table, field, constraint, index, relationship, dan migration. |
| `RINGKASAN-ARAHAN-MOCKUP-UI-<Project>.md` atau `UI-MOCKUP-DIRECTION-SUMMARY-<Project>.md` | Brief ringkas untuk arah mockup UI. File ini mengarahkan eksplorasi visual, bukan business scope. |
| `docs/01-....md` sampai set dokumen saat ini | Dokumen Blueprint individual yang diberi nomor sesuai urutan pipeline agar mudah dibaca dan ditelusuri. |
| `docs/implementation-sources/`, jika ada | Keputusan antara dengan ID stabil dan catatan sumber implementasi untuk audit serta pemeriksaan konsistensi. |
| `manifest.json` | Index yang dapat dibaca mesin untuk file paket, versi dan status dokumen, path, bahasa, nama parameter environment, dan urutan prompt. Baca file ini terlebih dahulu, bukan menebak nama file. |

Di root arsip, implementation kit menambahkan tepat delapan file Markdown:

| # | File | Kegunaan |
| --- | --- | --- |
| 1 | `AGENT.md` | Pointer kompatibilitas ke kontrak agent kanonik. |
| 2 | `AGENTS.md` | Aturan kerja permanen untuk coding agent. |
| 3 | `PROMPT_1.md` | Menganalisis PRD dan repository, lalu membuat atau merekonsiliasi development foundation dan plan. |
| 4 | `PROMPT_2.md` | Membangun prototype yang sudah ditinjau tanpa memulai full production implementation. |
| 5 | `PROMPT_3.md` | Memulai atau melanjutkan satu task production yang memenuhi syarat per run. |
| 6 | `PROMPT_4.md` | Mengoordinasikan multi-agent opsional ketika pekerjaan independen dapat dijalankan secara paralel dengan aman. |
| 7 | `PROMPT_5.md` | Melanjutkan pekerjaan yang terputus dari state yang tercatat di repository. |
| 8 | `PANDUAN_IMPLEMENTASI_AI_CODING_AGENT_UNTUK_USER.md` atau `AI_CODING_AGENT_IMPLEMENTATION_GUIDE_FOR_USERS.md` | Panduan pemula dalam bahasa Blueprint/PRD. Setiap ZIP hanya berisi file yang sesuai, bukan keduanya. |

Root juga berisi `.env.local` sebagai template placeholder yang aman dan `.gitignore` untuk mencegah secret lokal masuk ke Git. Kedua file tersebut tidak termasuk dalam delapan file Markdown implementation kit.

<Note>
  Project ZIP berisi specification dan file workflow, bukan repository aplikasi yang sudah selesai. Coding agent membuat atau merekonsiliasi source code setelah membaca paket dan Anda meninjau plan yang dibuatnya.
</Note>

<Warning>
  Jangan pernah commit nilai nyata dari `.env.local`. Pastikan file tetap diabaikan oleh Git, tambahkan secret hanya ke environment lokal atau deployment, dan jangan menempelkannya ke prompt coding agent, log, atau screenshot.
</Warning>

## Cara bahasa dipilih

Implementation kit memiliki varian bahasa Inggris dan Indonesia yang sudah ditinjau. Proses export memilih satu varian lengkap hanya berdasarkan bahasa dokumen Blueprint/PRD:

- Blueprint/PRD berbahasa Indonesia menerima file agent, prompt, dan `PANDUAN_IMPLEMENTASI_AI_CODING_AGENT_UNTUK_USER.md` dalam bahasa Indonesia; dan
- Blueprint/PRD berbahasa Inggris menerima file agent, prompt, dan `AI_CODING_AGENT_IMPLEMENTATION_GUIDE_FOR_USERS.md` dalam bahasa Inggris.

Mengubah bahasa interface tidak menulis ulang paket. Bahasa PRD menentukan output.

Prompt bersifat statis dan universal. Prompt tidak dibuat ulang, tidak disisipi detail project, dan tidak ditulis ulang untuk use case tertentu pada setiap download. Prompt yang sama dapat digunakan untuk berbagai produk karena coding agent membaca PRD dan repository saat Anda menjalankannya.

## Blueprint existing menerima kit yang sama

Format paket ini berlaku untuk Blueprint baru maupun Blueprint yang sudah dibuat sebelum implementation kit tersedia. Anda tidak perlu meregenerasi PRD atau dokumen Blueprint hanya untuk mendapatkan kit.

Export ulang Blueprint existing setelah syarat review dan approval saat ini terpenuhi. ZIP baru menyertakan delapan file Markdown sesuai bahasa dan template `.env.local`, sekaligus mempertahankan PRD terkonsolidasi, dokumen Blueprint, dan manifest. ZIP yang sudah tersimpan di perangkat tidak diperbarui secara otomatis.

## Gabungkan paket dengan aman

<Steps>
  <Step title="Ekstrak ke folder terpisah">
    Jangan coding di dalam arsip terkompresi. Ekstrak ke folder terpisah, periksa `manifest.json`, lalu mulai dengan membaca panduan implementasi sesuai bahasa.
  </Step>
  <Step title="Pertahankan aturan project yang sudah ada">
    Pada repository baru, letakkan `AGENTS.md` dan `AGENT.md` di root. Pada repository existing, rekonsiliasikan aturan yang relevan dengan instruksi agent yang sudah tersedia. Jangan menimpa instruksi manusia, source code, konfigurasi, atau perubahan lokal.
  </Step>
  <Step title="Salin input produk">
    Tambahkan PRD terkonsolidasi dan dokumen Blueprint ke workspace target agar coding agent dapat menggunakannya sebagai sumber kebenaran produk.
  </Step>
  <Step title="Rekonsiliasikan konfigurasi lokal">
    Jika repository sudah mempunyai `.env.local`, pertahankan seluruh nilai yang ada. Gunakan file dari ZIP hanya sebagai referensi aman untuk nama yang belum tersedia, lalu pastikan file lokal tetap diabaikan oleh Git.
  </Step>
  <Step title="Periksa Git">
    Gunakan remote repository yang sudah ada. Berikan URL Git hanya jika repository belum memiliki remote; jangan pernah mengganti remote existing tanpa persetujuan eksplisit.
  </Step>
</Steps>

`AGENTS.md` adalah kontrak agent kanonik. `AGENT.md` sengaja menunjuk ke file tersebut agar dua salinan aturan kerja tidak berbeda.

## Jalankan lima prompt secara berurutan

| Langkah | Prompt | Waktu penggunaan |
| --- | --- | --- |
| 1 | `PROMPT_1.md` | Jalankan satu kali saat memulai, atau ketika development foundation belum tersedia. Tinjau plan yang dihasilkan sebelum melanjutkan. |
| 2 | `PROMPT_2.md` | Jalankan setelah foundation dan plan ditinjau untuk membangun prototype yang terbatas. |
| 3 | `PROMPT_3.md` | Jalankan berulang kali. Setiap run hanya menyelesaikan atau melanjutkan satu task production yang memenuhi syarat. |
| 4 | `PROMPT_4.md` | Opsional. Gunakan hanya jika platform mendukung beberapa agent dan task yang dipilih benar-benar independen. |
| 5 | `PROMPT_5.md` | Recovery kondisional. Gunakan setelah interupsi, kegagalan agent, atau perangkat restart. |

Jangan menjalankan Langkah 4 hanya agar pekerjaan terlihat lebih cepat. Pertahankan satu koordinator, ownership yang eksplisit, dan urutan integrasi yang jelas ketika mode multi-agent aktif.

## Urutan source of truth untuk coding agent

1. `manifest.json` mengidentifikasi file, versi, dan workflow dalam paket ini.
2. `Blueprint-PRD-<Project>.md` menentukan scope implementasi dan acceptance criteria yang disetujui.
3. Skema database lengkap menentukan constraint persistence dan migration.
4. File di dalam `docs/` memberi detail domain dan traceability yang terfokus.
5. Human PRD membantu review, sedangkan file arahan mockup UI membantu eksplorasi visual.
6. `AGENTS.md`, panduan implementasi sesuai bahasa, dan lima prompt mengatur cara pekerjaan coding dilakukan; file tersebut tidak menambahkan fitur produk.

Jika dua file produk otoritatif benar-benar bertentangan, berhenti sebelum implementasi, tampilkan nama file dan dampaknya, lalu minta keputusan. Jangan biarkan coding agent mengarang penyelesaiannya.

## Sebelum memberi prompt pertama

1. Ekstrak arsip ke folder normal, lalu baca `manifest.json`.
2. Baca panduan implementasi sesuai bahasa, `AGENTS.md`, PRD terkonsolidasi, skema lengkap, dan file `docs/` yang relevan.
3. Pastikan aturan repository, source code, konfigurasi, dan perubahan lokal yang ada akan dipertahankan.
4. Rekonsiliasikan `.env.local` tanpa menambahkan atau mengekspos secret nyata, lalu pastikan file tersebut tetap diabaikan oleh Git.
5. Buat atau verifikasi Git baseline sebelum coding agent mengubah file.
6. Berikan `PROMPT_1.md` kepada coding agent. Tinjau penjelasan produk, conflict, risk, acceptance criteria, development foundation, dan plan sebelum memakai `PROMPT_2.md`.
7. Setelah setiap prompt berikutnya, jalankan pemeriksaan repository, tinjau UI jika relevan, periksa `git diff`, dan commit hanya pekerjaan yang sudah diverifikasi sebelum melanjutkan ke tahap berikutnya.

Jika regenerasi, restore, atau versi baru membatalkan approval global Blueprint, tinjau dan setujui kembali set saat ini sebelum mengunduh ZIP pengganti.
