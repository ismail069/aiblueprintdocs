---
title: "Glosarium"
description: "Definisi istilah produk, dokumen, revisi, pembayaran, dan implementasi yang digunakan di AI Blueprint."
---

| Istilah | Arti |
| --- | --- |
| **AI credit** | Unit pemakaian produk untuk tindakan AI yang memenuhi syarat. Credit bukan uang dan berbeda dari biaya penyedia pembayaran. |
| **App Map / App Structure** | Peta terstruktur area dan capability aplikasi. Secara default ini bukan source code atau site map. |
| **Blueprint** | Paket perencanaan terhubung untuk satu ide produk. Blueprint bukan satu dokumen atau satu jawaban chat. |
| **Blueprint Assistant** | Assistant yang memahami konteks project untuk pertanyaan, proposal, dan revisi yang didukung. Jawaban chat saja tidak mengubah dokumen. |
| **Blueprint Summary** | Ringkasan workspace untuk kesiapan dokumen, progres review, project health, versi, download, dan next action. |
| **Versi saat ini** | Keadaan dokumen atau seluruh Blueprint yang sedang aktif di workspace. Versi sebelumnya tetap berada di history. |
| **Direct edit** | Perubahan literal sempit yang disetujui pada satu leaf document tanpa menulis ulang dokumen yang tidak terkait. |
| **Dokumen** | Satu sudut pandang perencanaan dalam Blueprint, misalnya Application Journey atau Access & Security. |
| **Generation / regeneration** | Pembuatan set dokumen atau penulisan ulang scope terdampak setelah proposal ditinjau. |
| **Idea Review / Smart Requirement Summary** | Pemahaman terstruktur atas ide yang ditinjau sebelum generation awal. |
| **Manifest** | Index Project ZIP yang dapat dibaca mesin untuk file, versi, path, bahasa, dan urutan workflow. |
| **Tidak Diperlukan** | Stub dokumen aktif yang valid karena artefak tidak membutuhkan konten implementasi untuk produk tersebut. Stub tetap perlu ditinjau. |
| **Payment history** | Catatan aplikasi mengenai checkout dan outcome pembayaran yang sudah dikonfirmasi provider. Redirect browser bukan bukti pembayaran selesai. |
| **Proposal** | Rencana perubahan yang disiapkan untuk review. Tidak ada dokumen berubah sampai proposal diterapkan. |
| **Project health** | Ringkasan yang membedakan note, risiko, state repair, pekerjaan before go-live, dan blocker. |
| **Project ZIP** | Handoff implementasi yang sudah disetujui, berisi dokumen produk, PRD, manifest, placeholder konfigurasi, dan workflow coding agent. ZIP bukan aplikasi jadi. |
| **Review / Ditinjau** | Catatan bahwa dokumen saat ini telah dibuka untuk inspeksi manusia. Ini bukan approval Blueprint. |
| **Restore** | Memindahkan seluruh Blueprint ke snapshot lama sambil mempertahankan history. Set aktif hasil restore dapat perlu ditinjau dan disetujui kembali. |
| **Revision history** | Riwayat tingkat dokumen untuk perubahan satu dokumen. Berbeda dari riwayat versi seluruh Blueprint. |
| **Sign Approve Blueprint** | Persetujuan set versi aktif lengkap setelah review; tindakan ini membuka export Project ZIP yang memenuhi syarat. |
| **VPC / Validated Product Context** | Konteks produk yang sudah disetujui dan menjadi dasar generation dokumen terhubung. |
| **Version** | Snapshot seluruh Blueprint yang dapat dipulihkan. Version tidak sama dengan status review atau approval. |

Jika label di workspace Anda berbeda dari glosarium ini, gunakan makna yang ditampilkan interface saat ini dan hubungi Support bila perbedaan tersebut memengaruhi keputusan approval atau pembayaran.
