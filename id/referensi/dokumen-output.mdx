---
title: "Dokumen Blueprint"
description: "Sepuluh dokumen perencanaan yang tampil ke customer dan kapan setiap dokumen relevan."
---

Semua dokumen memakai konteks produk yang sama. Database Schema bersifat kondisional; isi lainnya juga menyesuaikan ide dan keputusan yang Anda setujui.

| Dokumen | Tujuan |
| --- | --- |
| **Smart Requirement Summary** | Produk, user, masalah, hasil, keputusan, asumsi, dan pertanyaan terbuka. |
| **Application Journey** | Alur end-to-end, status, handoff, guard, kegagalan, dan recovery. |
| **Technical Foundation** | Arsitektur, teknologi, storage, queue, observability, recovery, dan arah deployment. |
| **Database Schema** | Entitas, relasi, constraint, lifecycle, dan batas data. Hanya dibuat ketika persistence relevan. |
| **App Map** | Area produk, kapabilitas, aktor, dan tanggung jawab journey—bukan daftar screen atau route. |
| **Access & Security** | Autentikasi, otorisasi, peran, scope, audit, dan kontrol keamanan. |
| **Lean Canvas** | Masalah, solusi, user, nilai, kanal, biaya, dan asumsi pendapatan. |
| **MVP Scope** | Requirement produk, batas MVP, prioritas, pengecualian, risiko, dan acceptance criteria. |
| **Requirement Coverage** | Requirement EARS, acceptance criteria, traceability, kontradiksi, dan gap. |
| **UI/UX Design** | Behaviour UX, state, aksesibilitas, responsivitas, dan quality check. |

<Note>
  Rangkaian output mengikuti kebutuhan produk. Hasil **Tidak Diperlukan** valid jika dokumen tersebut tidak menambah informasi implementasi yang relevan.
</Note>
